# 智能水务算法管理平台前端

这是连接 FastAPI 后端的 Angular 21 前端工程，覆盖认证、数据资产、算子中心、可视化工作流、业务场景、异步运行和结果追溯。算法运行统一通过工作流完成；S01 漏损候选结果仍须结合现场与业务规则人工核验。

参与开发前请先阅读 [前端贡献指南](CONTRIBUTING.md)，其中说明了当前项目的模块边界、前后端协作方式、提交检查和 CI 流程。

## 技术边界

- Angular 21（Standalone Components、Router、Signals）与 Angular Material。
- Apache ECharts 6：质量、预测和异常检测的时序结果展示。
- Rete.js 2：工作流 DAG 可视化编排（节点拖拽、连线、参数配置）。
- Dockview：工作流编辑器可拖拽面板布局。
- NGX Formly：算子参数动态表单渲染。
- AG Grid Community：任务中心高性能表格。
- 浏览器只访问相对路径 `/api`、`/health`；开发服务器代理到本机 `localhost:18000`。
- 登录令牌仅保存在 `sessionStorage`，关闭浏览器标签页会清除；不提交任何账号、Token、服务器地址或中间件地址。
- 后端仍是权限的最终裁决者。前端权限控制只负责隐藏不适用的菜单和操作。

## 前置条件

1. Node.js 24.x 与 npm 11.x（当前工程使用 Angular 21.2）。
2. 已启动或已转发后端到本机 `localhost:18000`。远程联调时，在 VSCode Remote Ports 中把服务器 `18000` 转发到本机 `18000`。
3. 测试账号由使用者在登录页手动输入，不写入文件。

## 本地启动

```powershell
npm ci
npm start
```

浏览器打开 `http://localhost:4200`。启动命令会自动读取 [proxy.conf.json](proxy.conf.json)：

```text
浏览器 http://localhost:4200/api/...
  → Angular 开发代理
  → http://localhost:18000/api/...
  → 已转发的 FastAPI 服务
```

WebSocket 的 `/api/v1/ws/tasks/{task_id}` 同样通过代理转发。业务源码不可写服务器 IP、SSH 信息、数据库 URI 或 Redis/MinIO/RabbitMQ 地址。

若只想在没有后端的情况下查看静态页面，可运行 `npm run start:direct`；此模式不会代理 API，因此登录和业务数据会失败是预期行为。

## 演示步骤

1. 登录后在首页查看平台概览（`/api/v1/portal/summary`）：有效用户、数据资产、工作流、运行中任务、平台负载、最近资源。
2. 在"数据源与导入"上传 CSV，查看表头预览并完成点位、时间、指标和值来源映射；或接入只读 MySQL 后发起导入。
3. 进入"算子中心"查看端口、参数、成熟度和可运行状态；算子中心不直接执行任务。需要导入外部算法时进入"导入外部算法"。
4. 点击"新建工作流"，从内置模板列表选择起始结构（动态从 `/api/v1/workflow-templates` 获取），创建草稿后进入编辑器。
5. 在 Rete 画布拖拽、连线和调参，校验后保存草稿并发布版本；运行时按数据资产、版本、点位、指标和值来源逐级绑定输入。
6. 进入"工作流运行记录"，观察 WebSocket 推送；连接中断时会每 2 秒轮询任务和日志。
7. 运行详情页按节点展示状态、参数快照、日志和 artifact；最终输出使用通用渲染器显示时序、表格、标量、候选列表、报告或 JSON。
8. 进入"场景中心"，选择已上线的 S01 DMA 分区漏损评估，绑定四路数据（进水流量、授权用水量、合法夜间用水量、管网压力），设置质量门槛和采样间隔，一键运行。
9. S01 运行完成后查看风险时间线、候选时段和报告；候选仍需人工核验。GPU 算子在运行时环境未验收前由后端标记为不可用，前端不解除限制。

数据资产默认仅创建者与管理员可见。CSV 原件由后端保存到 MinIO，浏览器不会得到 MinIO 凭据或直连下载地址；只读 MySQL URI 输入框也不会回显密码。

## 工作流与算子页面

登录后进入"算子中心"查看受审核的算子契约和内置结构。进入"工作流"可以从草稿、已发布版本或内置模板创建流程；Rete 编辑器支持节点目录点击/拖入、节点拖动、端口连线（含数据类型校验）、输出端口声明、参数类型控件、画布适应、撤销/重做和 Graph 序列化。保存、校验和发布仍由后端裁决。

新建流程通过"工作流启动器"（`/workflows/new`）选择内置模板。S01 漏损场景通过黑盒页自动完成模板解析、草稿创建、数据绑定、发布和运行，无需手动编排。工作流运行记录详情页展示节点状态、参数快照、日志、artifact 和最终结果，刷新后可从 REST 接口恢复状态。

工作流草稿同时保存在服务端和浏览器 IndexedDB（`WorkflowCacheService`），刷新页面可恢复未保存的编辑内容；服务端草稿为最终权威。

目录约定：

```text
src/app/core/       认证、HTTP、拦截器、任务追踪、错误处理、DTO、S01 场景服务、工作流缓存
src/app/shared/     数据资产选择器、状态标签、图表、血缘树、参数表单等不依赖具体接口的通用组件
src/app/features/   登录、首页、场景中心、数据资产、算子中心、工作流、任务、结果、用户、回收站、运行详情
src/app/layout/     已登录后的导航外壳
```

新增 API 时，先在 `core/models/api.models.ts` 固化 DTO，再由 feature 调用 `ApiClient`；不要让图表组件解析后端原始响应。新增路由应保持懒加载，避免 ECharts 等大依赖进入登录首屏。

## 常见问题

- **401 / 自动跳回登录**：Token 已失效，拦截器会自动尝试刷新；刷新失败后重新登录即可。不要把 Token 写入 localStorage 或代码。
- **健康检查失败 / 请求 `ECONNREFUSED`**：确认 VSCode 的 `18000 → localhost:18000` 端口转发还在，或确认本机后端正在监听 18000。
- **CORS 报错**：正常代理模式下浏览器访问的是 `4200`，由开发服务器转发，通常不需要额外改 CORS；只有绕过代理直连后端时，才需后端显式允许前端 Origin。
- **WebSocket 断开**：任务页会自动使用轮询回退；最终状态以任务查询接口和后端 MySQL 记录为准。
- **GPU 算法不可点**：算子的 `available` 字段由后端根据运行时环境状态决定，前端不硬编码禁用特定算法。
- **工作流草稿丢失**：检查 IndexedDB 中是否有本地恢复草稿；服务端草稿为最终权威，多标签页编辑时以 `expected_revision` 做乐观锁。
